# 데이터 정제 코드 정리 (v1~v5, 버전당 1개)

이 폴더는 전체 데이터 파이프라인 코드 중에서, **버전별로 "무엇이 바뀌었는지"를 가장 잘 보여주는
핵심 파일 1개씩만** 뽑아놓은 것이다. (모델링 관련 코드는 각자 팀원이 본인 파트를 정리하므로
여기 포함하지 않음.)

## 왜 이 5개 파일을 골랐는가

v1~v5는 전처리를 매번 처음부터 다시 한 게 아니라, **이전 버전 결과물을 이어받아 그 위에 특정
문제만 고치는 방식**으로 진행됐다. 그래서 "버전당 1개"를 고를 때, 그 버전에서 전체 파이프라인을
돌리는 메인 스크립트가 아니라 **그 버전의 핵심 변경사항을 담당하는 파일**을 기준으로 선택했다.
그래야 파일 하나만 봐도 "이 버전에서 뭘 했는지"가 바로 드러난다.

| 버전 | 선택한 파일 | 원본 경로 | 왜 이 파일인가 |
|---|---|---|---|
| v1 | `v1_preprocess_data.ipynb` | `preprocess_data.ipynb` | 전처리 자체가 아직 스크립트화 전, 노트북 하나가 v1의 전체 작업 단위였음 |
| v2 | `v2_preprocess_data.py` | `preprocess_data_v2.py` | 노트북을 스크립트로 재작성하면서 정책(청크 처리 방식 등)을 명시적으로 분리한 버전의 메인 파일 |
| v3 | `v3_preprocess_data.py` | `preprocess_data_v3.py` | v3의 핵심 변경사항(4초 미만 청크 필터링)이 직접 들어간 전처리 메인 스크립트 |
| v4 | `v4_data_cleaning.py` | `build_processed_v4_pools.py` | v4는 전처리를 다시 돌리지 않고 **v3 결과물에서 보컬 섞인 MUSAN 음악을 걸러내는 것**이 유일하고 핵심적인 "정제" 작업이라, 전처리 메인 스크립트가 아니라 이 필터링 스크립트가 v4를 대표함 |
| v5 | `v5_data_cleaning.py` | `build_mixed_dataset_v5.py` | v5도 전처리를 새로 안 하고, v4 혼합 데이터의 일부를 배경잡음 버전으로 교체하는 것이 핵심 작업이라 이 스크립트가 v5를 대표함 |

## 공통 원칙

- v1~v3는 "원본 오디오 → 표준화된 청크"를 만드는 **전처리 메인 스크립트**가 그 버전의 전부였기
  때문에 그대로 선택
- v4~v5는 전처리를 재실행하지 않고 **이전 버전 결과물에 대한 수정/증강**만 했기 때문에, 전체
  파이프라인 스크립트(`build_mixed_dataset_v{4,5}.py`, `augment_pools_v{4}.py` 등) 대신
  **그 버전에서 실제로 새로 한 일을 담당하는 파일 하나만** 선택
- 각 파일은 실행에 필요한 설정 파일(`mix_config_v3.py` 등)이나 공용 유틸(`augment_common_v3.py` 등)과
  함께 있어야 실제로 돌아가지만, 여기서는 "버전당 1개"라는 요청에 맞춰 **그 버전의 정체성을 보여주는
  핵심 파일만** 남겼다. 전체 실행 가능한 코드는 원본 작업 폴더에 별도로 있다 (이 레포에는 미포함).

## 더 자세한 설명

버전별 전체 작업 내용, 실제 생성된 데이터 통계, 라벨/데이터셋 비율 표는 원본 작업 폴더의
`DATASET_GUIDE_V1_TO_V5.md`에 정리돼 있다 (이 레포에는 미포함; 필요하면 추가 요청).
